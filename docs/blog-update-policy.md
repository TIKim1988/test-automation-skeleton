# 기술 블로그 갱신 정책

기술 블로그는 모든 커밋을 복제하는 곳이 아니라, 재사용 가능한 의사결정과 학습을 기록하는 공개 문서입니다.

## 블로그를 갱신하는 경우

- 테스트케이스 모델·자동화 아키텍처·실행 정책이 변경됐을 때
- 신규 기능군 자동화가 완성됐을 때
- 반복 실패를 해결해 재발 방지 기준을 만들었을 때
- 월간 품질 지표나 운영 회고를 공개할 가치가 있을 때

## 갱신하지 않는 경우

- 셀렉터 한 줄 수정, 오탈자, 의존성 단순 갱신
- 아직 검증되지 않은 임시 workaround
- 시크릿·실서비스 고객 데이터가 포함될 수 있는 변경

## 작성 흐름

1. 이 저장소의 `CHANGELOG.md`에 사용자 영향이 있는 변경을 짧게 기록합니다.
2. 의미 있는 변경이면 `TIKim1988.github.io`에 배경, 선택한 이유, 결과, 다음 과제를 담은 글을 작성합니다.
3. 코드 저장소와 블로그 저장소의 커밋은 독립적으로 검토·배포합니다. 블로그 갱신 실패가 자동화 배포를 막아서는 안 됩니다.
