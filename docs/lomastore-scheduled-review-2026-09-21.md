# 로마스토어 예약 실행 재검토

확인일: 2026-09-21. GitHub 실행 이력, 최근 3회 작업 로그, 수정 브랜치의 실제 CI 로그, 두 브랜치 코드를 비교했어. 아래 진단은 병합 전 기준이고, 이어서 진행한 main 통합과 실사이트 검증 결과는 마지막 절에 구분했어.

## 결론

실패가 비슷한 직접 원인은 수정 코드가 예약 실행에 반영되지 않은 거야. 기본 브랜치는 main이고 9월 8~21일 예약 실행 14회 모두 main의 `85b4056`을 실행했어. 수정 커밋 `c5974c0`은 `codex/automation-operability`에만 있어. 이전 작업은 브랜치 푸시까지 완료했지만 예약 운영 반영은 완료하지 못했어.

## 별도의 운영 오류

최근 3회 모두 Sync failure issues에서 `could not add label: 'test-failure' not found`로 실패했어. 테스트 자체 실패와 이슈 등록 실패가 함께 존재해. Run Playwright tests가 단계 화면에서 success로 보이는 건 continue-on-error 설정 때문이며 테스트 로그에는 exit code 1이 있어. 최종 실패 판정 단계는 앞선 이슈 등록 오류 영향으로 skipped 상태야.

main의 이슈 동기화 코드는 현재 실패 목록에 없는 기존 이슈를 통과 확인 없이 닫아. smoke 분리를 적용하면서 이 코드를 그대로 유지하면 실행하지 않은 회귀 TC의 이슈까지 닫힐 수 있어. 실제로 실행하고 통과한 ID만 닫도록 수정해야 해.

## 추천 반영 순서

1. main과 수정 브랜치를 통합하되 main에 추가된 HOME-003~008 6개 TC와 healing 변경을 별도 검토해. main은 29개, 수정 브랜치는 23개여서 브랜치 전체 덮어쓰기는 안 돼. 추가 6개도 CSV 명세에 등록해야 해.
2. 수정 브랜치의 셀렉터, 공통 준비, 기대 결과, 상태 처리와 리포트 수정사항을 반영해. 배너와 인기상품의 추가 실패 4건은 현재 화면에 맞춰 따로 수정해.
3. 예약 실행은 smoke, 수동은 smoke/regression/all로 구분하되 전체 29개 추적을 보존해. 전체 회귀와 smoke 성공률을 직접 비교하지 않아야 해.
4. 이슈 라벨 준비와 안전한 종료 조건을 고치거나 이슈 동기화를 명시적으로 분리해. 메일 설정은 main에서 성공한 GMAIL_SECRET_KEY 구성을 보존해야 해. 수정 브랜치의 메일은 다른 secret 이름을 쓰며 push 때 skipped였으므로 메일 성공은 검증된 적 없어.
5. 통합 커밋을 검증한 뒤 main에 반영하고, 첫 실행의 head_sha, 실행 TC 수, 메일 결과를 함께 확인해. 보고서에 브랜치와 커밋, suite를 표시하면 같은 혼동을 줄일 수 있어.

수정 브랜치 smoke 성공은 9월 8일 당시 결과야. 9월 21일 현재 전체 29개가 통과한다는 증거는 아니야. 가격 정렬 불일치 2건의 현재 상태도 이번 로그만으로 갱신할 수 없어.


## main 통합과 재검증

사용자 요청으로 main의 추가 6개 TC, 환경변수 지원, 화면 요소 기록 기능을 보존하면서 수정 브랜치를 통합했어. CSV와 YAML은 전체 29개, smoke 11개, regression 18개야.

- 정적 검사, CSV 동기화, 단위 테스트 20개 통과.
- 전체 실행: 26개 통과, 3개 실패, skip 0, flaky 0. 약 119초, 재시도 없음.
- URL 이동 대기를 추가한 뒤 최종 smoke: 10개 통과, HOME-007 실패, skip 0, flaky 0. 약 51초, 재시도 없음.
- 화면 숫자가 애니메이션 컴포넌트로 변경되어 수량과 가격을 못 읽던 문제를 수정했어. 숨겨진 이전 숫자를 제외한 현재 표시 숫자로 계산을 검증해.
- SEARCH-002와 STORE-002는 실제 표시 판매가의 순서 불일치가 재현됐어. 가격 목록 증거를 저장했고 실패 검증을 유지했어.
- HOME-007은 약관 링크 클릭 시 React 오류 #418이 기록됐고, 15초 뒤에도 홈에 남았어. 화면이 안정된 뒤 수동 브라우저에서는 약관 페이지로 이동했어. 초기 렌더링 시점 문제로 추정하지만 원인은 확정하지 않았어. 직접 URL 이동이나 클릭 재시도로 실패를 숨기지 않았어.
- 이 저장소는 테스트 코드 저장소라 사이트의 React 오류와 가격 정렬 구현 자체는 수정하지 못했어.
- 이슈 동기화는 라벨을 준비하고 실제 실행한 모든 프로젝트가 통과한 TC만 닫게 수정했어. 기존 메일 인증 설정을 보존했어. push 실행은 메일과 이슈 갱신을 하지 않으므로 예약 실행에서의 동작은 별도 확인이 필요해.
