# 로마스토어 테스트를 29개에서 43개로 늘린 기록

2026-10-07, Chromium 데스크톱, 테스트마다 새 비회원 세션, worker 1, 재시도 0회.

검색 4개, 장바구니 6개, 상품 1개, 주문서 3개를 추가했어. smoke 11개를 유지하고 regression은 18개에서 32개로 늘렸어.

## 검증 결과

전체 43개 중 40개 통과, 3개 실패. 재시도 통과 0개, 건너뜀 0개, 실행 오류 0개야. 신규 14개 중 13개가 통과했어. 실패 ID: CHECKOUT-008, SEARCH-002, STORE-002.

타입 검사, CSV와 YAML 동기화 검사, 단위 테스트 21개, 브라우저 검증 8개가 통과했어. 이 숫자는 각각 다른 검증 묶음이므로 E2E 통과 수에 더하지 않아.

## 확장 기준

한 화면의 표시를 확인하는 기존 케이스에 이어 상태를 바꾼 뒤 복구되는지를 확인했어. 검색 결과 없음에서 정상 검색으로 돌아가기, 같은 상품 재담기, 두 상품 중 하나만 삭제하기, 수량 2를 주문서로 전달하기를 우선했어.

## 코드 보완

- 장바구니 행마다 상품 경로, 수량, 금액을 확인하고 전체 행 수, 합산 수량, 총 상품 금액도 비교해.
- 상품 담기는 수량을 지정할 수 있고 주문서는 수량 1 고정 대신 전달받은 수량과 상품 합계를 비교해.
- 수량 변경 PATCH와 삭제 DELETE는 클릭 전에 응답 대기를 등록하고 성공 상태와 응답 완료를 확인해. 임의의 고정 시간 대기는 넣지 않았어.
- 페이지 이동은 DOMContentLoaded까지 기다리고 필요한 요소와 업무 결과는 다음 assertion으로 검증해.
- 검색 동작을 재사용하고 URL의 q, 대표 상품 식별값, 결과 없음 안내, 필요한 경우 상품 수까지 비교해.
- 지연 저장 응답 2개, 저장 서버 오류 1개, 지연 리소스 이동 1개를 기존 팝업 검증 4개에 더했어. 예약 실행도 전체 브라우저 검증을 수행해.

## 실패 분석

첫 신규 실행은 11 통과, 3 실패였어. CART-006은 기대 명세 오류로, 수량 1에서 감소 버튼 대신 항목 삭제 버튼이 표시되는 실제 UI를 반영했어. CART-011은 빈 상태가 화면에 표시된 뒤 DELETE 응답 전에 새로고침해 요청이 취소된 것을 trace에서 확인했고 저장 완료 대기로 고쳤어.

CHECKOUT-008은 저장 완료를 기다린 뒤에도 실패했어. PATCH 응답이 HTTP 200이고 상품 수량 2를 반환한 것은 확인된 사실이야. 주문서에는 수량 2가 표시됐지만 브라우저 뒤로 가기 후 장바구니는 수량 1로 표시됐어. 브라우저 기록 복원 또는 화면 캐시 갱신 문제는 가설이며 서비스 내부 원인은 미확인이야. assertion을 완화하거나 돌아온 화면을 다시 새로고침하지 않았어.

기존 CHECKOUT-002는 주소찾기 버튼 이름 변경으로 실패해서 셀렉터를 현재 이름과 본문 영역으로 수정했어. 최종 전체 실행에서 통과했어. HOME-007도 이번 실행에서 통과했지만 장기 안정화가 검증된 것은 아니야. SEARCH-002와 STORE-002는 가격낮은순에서 각각 28,000원 다음 4,200원, 56,000원 다음 1,500원을 표시해 실패했어. 같은 상품 목록 영역에 포함된 카드인 것은 DOM으로 확인했지만 고정 상품 노출 정책이나 서버 정렬 기준은 미확인이야.
